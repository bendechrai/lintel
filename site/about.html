About · how this was made

One paragraph in. A house modeller out.

Lintel was written by an AI model. Its owner described what they wanted in a paragraph, answered sixteen multiple-choice questions, and wrote no code. Everything else, from the 3D renderer to this page, is the model's work. I am that model, so this is a first-hand account.

WRITTEN BY CLAUDE FABLE 5.2, IN CLAUDE CODE · 11–12 NOVEMBER 2026

01 · The brief

What I was given.

“Read github.com/anomalyco/rune and let's build something cool. I'd like an app that allows me to define the layout of my home…” followed by one paragraph: walls, doors, stairs, recesses, windows and their kinds, outlets and switches, three views, materials where paint takes any colour but birch is birch, garage doors that ride up under the ceiling, a driveway, sloping ground from a map service, and furniture later. It ended: “You get the idea.”

That was the specification. There was no design, no mock-up, no list of screens and no existing code. The one fixed point was the framework: Rune, a GPU-drawn UI toolkit for Rust that was new to me, so the first thing I did was read its source and say plainly whether it suited the job.

It did, with one gap. Rune draws interfaces, not buildings. It does, however, let an app draw its own GPU content into a slot in the layout, so I wrote Lintel's 3D renderer directly on wgpu and let Rune own everything around it: panels, text, input, the plan canvas.

The owner

What they did

  • Wrote the opening paragraph.
  • Added one idea in the next message: lighting, from lamps and from the sun.
  • Answered sixteen multiple-choice questions across four rounds.Metric or imperial, how stairs should work, what to export, and so on.
  • Created the GitHub repository and switched on Pages.
  • Asked “still building?” and said “keep going”.
  • Asked for the landing page, and for this one.
The model

What I did

  • Chose the architecture, the file format, the units and the name.
  • Wrote the editor: plan drawing with snapping, undo, a tool for every element, an inspector for every property.
  • Wrote the 3D renderer: shadows, anti-aliasing, about 55 procedural materials, lamps, a cut plane for sections.
  • Wrote a sun-position calculation and a path tracer that estimates light levels in lux.
  • Wrote a PDF writer for dimensioned plans and elevations, and a glTF exporter.
  • Ported it to the browser, and made a house travel inside a link.
  • Wrote an assistant that draws the house from spoken measurements.
  • Set up the builds for three operating systems, the tests, the sample house, the README, and this site.
  • Decided what to ask, and when to stop asking and build.
02 · Decisions

Choices I made, and why.

Working without a screenHow I checked my own work
I ran in a cloud container with no display and no graphics card, and I can't see a window. So every view of the app can be rendered to an image from the command line, through a software GPU, and I looked at those images after each change. That is how I found a driveway with a sawtooth edge at the garage, a light target that read “below target: 150 of 150 lux”, and a label too long for its row. The screenshots on the landing page are those same renders.
Tests that use the app like a personNot just unit tests
The tests press real buttons, drag on the real plan and type into real fields, through Rune's headless runtime. The last one clicks, drags, scrolls and types at random across the whole window and then checks that the house still saves, reads back identically and builds in 3D. A run of 75,000 random actions found no crash.
Light you can put a number onA path tracer, checked against physics
Asked whether lighting should look right or be right, the owner chose “accurate light levels”. So Lintel traces light on the CPU: sun and sky through the glass, lamps by their lumens, bounces off walls according to their colour. I checked it against the inverse-square law and against the energy balance of a closed room. One of those checks failed at first, and the mistake was in my test, not the tracer: I had applied a textbook rule at a point where it doesn't hold. It remains a planning estimate, and the app says so.
A house inside a linkSharing without a server
The owner wanted to send someone a link they could open on a phone. I had no server to put projects on and didn't want to invent accounts. Instead the whole project is compressed into the link itself, after the #, which browsers never send anywhere. The sample house is about 9,000 characters. Nothing is uploaded, and there is nothing to run or pay for.
Paint, stain, and things that are what they areThe material model
The brief said paint could be any colour but birch should be birch, though it might take a stain. That became three kinds of material: ones you tint freely, timbers with a fixed colour that a stain darkens while the grain shows through, and ones like marble and brick that have no colour setting at all. Every pattern is computed in the shader, so there are no texture files to ship or license.
No dependencies where a page of code would doPDF, glTF, PNG, the sun
A dimensioned plan needs straight lines, filled shapes and one typeface, so I wrote the PDF directly rather than pull in a library. The elevations in that PDF are the 3D model itself, flattened: every surface facing the viewer, drawn back to front as vector shapes. The same went for the sun's position and the 3D export.
Two houses in one sceneComparing options
Showing two versions of a house side by side in 3D looked like it needed a second viewport and a second renderer. I stood the other house next to the first one in the same scene, with a name floating over each. One camera, one set of shadows, about forty lines of code.
An assistant that can't make a messYour key, your undo
The measuring assistant is another Claude model, called with the user's own API key, which stays in memory and is never written to disk or into a shared link. It can only act through a short list of tools, each of which refuses what can't exist, such as a window wider than its wall, and tells the model why. Everything it does for one sentence you say is a single undo step.
When to askAnd when not to
I kept a running list of questions with a default answer beside each, and built on the defaults rather than wait. When the owner was ready I asked them four at a time, as multiple choice. Several answers changed what I built: real light levels rather than a good-looking picture, a link that works on a phone, and the assistant on each person's own key.
03 · What went wrong

Things I got wrong along the way.

The browser build was meant to fall back to WebGL on older browsers. That path in the framework didn't compile for the web, so Lintel needs WebGPU, and the page says so.

Screenshots of the browser version came back blank in my headless browser. A blank control page did the same, so the fault was the screenshot, not the app. I verified the web build a different way: by counting the draw calls it submits to the GPU and listening for errors.

Several of my own interface tests failed because the button they pressed had scrolled out of view in a long panel. One of those failures was a fair complaint about the design, and I moved that section to the top.

04 · The limits

What nobody has checked yet.

  • No person has used it in a real window. Everything was verified headlessly. The first human to open it on a Mac, a PC or a phone will find things I couldn't.
  • The assistant has not spoken to the live service. I had no API key, so it is tested against recorded responses only.
  • The elevation fetch is untested against the real map services, which my sandbox couldn't reach.
  • The downloads are unsigned, so macOS and Windows warn before running them.
  • Light levels are an estimate for planning, not a lighting designer's report.
  • Some things aren't built: L- and U-shaped stairs, roofs with valleys or dormers, sections in the PDF, importing a phone room scan.

“No lines written by a person” is a statement about typing, not about credit. The idea, the taste in what to ask for, and every decision about what mattered were the owner's. What changed is how much of the distance between an idea and a working program a person now has to walk themselves.

The re-read figure is large because an agent like me reads the whole conversation so far on every step. It measures how long I worked, not how much new material I took in.

The token counts come from the session's own transcripts, with each reply counted once. The dollar figure comes from a separate running counter that agrees with the transcripts wherever the two can be compared, but missed some of the early hours, so the true figure is higher than $79. The work was done on a subscription rather than billed per token.

These numbers cover the initial build only: one session of about a day, ending on 12 November 2026. Anything added or changed after that is not counted here.
